# 01 - 问题篇：为什么工程师要懂 LLM 底层

> 【本节问题】① "会调 API 就行，原理是算法工程师的事"——这句话错在哪？② 不懂底层的人会在哪四个地方翻车？③ 懂到什么程度算够？

---

## 1. 黄金圈 Why：你是"用模型的人"，不是"造模型的人"——所以要懂的是"行为规律"

**一句话人话**：司机不需要会造发动机，但必须懂油门刹车油耗——否则一上高速就出事。LLM 工程师同理：不用会训模型，但必须懂 **token 经济、上下文窗口、采样随机性、思考成本** 这四个"驾驶仪表"。

## 2. 四类翻车现场（每一条都是真实高频事故）

### 翻车 ①：不懂 token —— 账单爆炸与中文截断

- 把一段 3 万字合同发给"128K 上下文"的模型，失败了——不知道**中文字≈token 的换算**和"上下文里还有 system+历史要一起算"
- 输出价格是输入的 5 倍，让模型"详细展开说说"——成本直接 ×10
- 不知道 `max_tokens` 限制的是**输出**，以为是总长度

### 翻车 ②：不懂上下文窗口 —— "记忆"幻觉

- 以为模型记得上一轮会话（**每次调用都是失忆的**，是你自己把历史塞回去的）
- 以为窗口 1M = 可以无限塞文档（context rot：塞得越多，中间内容越容易被忽略）
- 多轮 Agent 循环里历史越滚越大，没人裁剪——延迟和成本双双爆炸

### 翻车 ③：不懂采样 —— 输出不可复现的困惑

- 同一个提示词两次结果不同就以为"有 bug"——其实 temperature>0 本来就掷骰子
- 对抽取任务用默认温度，格式漂移不知道为什么
- 反过来，以为 temperature=0 就一定正确（它只保证可复现）

### 翻车 ④：不懂推理模型 —— 成本黑洞与错误用法

- 给 R1/GPT-5 发一个"把日期格式转换一下"的简单任务——模型思考了 3000 token，成本 10 倍、延迟 10 倍
- 用提示词硬教推理模型"第一步…第二步…"——输出反而变差（001 篇讲过）
- 不知道思考 token 也按输出计费——月底账单里多出一大笔"看不见的消费"

## 3. 懂底层 → 读得懂官方文档的"潜台词"

| 官方文档黑话 | 底层知识 | 实际含义 |
|---|---|---|
| "context window 1M" | 02 卡5 | 输入+输出总和的上限，且长上下文可能加价 |
| "reasoning tokens are billed as output" | 02 卡10 | 思考过程也收输出价，Agent 场景成本大头 |
| "cached input tokens" | 02 卡12 | 前缀重复即可省钱，设计提示词要"稳定前缀在前" |
| "prefill is no longer supported" | 03 篇 | 不能再偷改模型的开头，锁格式改用结构化输出 |
| "batch API 50% off" | 06 篇 | 异步任务换端口，直接半价 |

## 4. 懂到什么程度算够？（本笔记的度）

- ✅ 够用线：能解释 token/窗口/采样/缓存/思考成本 五个仪表盘；能看懂 07 篇的格局表并做选型
- ✅ 加分线：能画出一次前向计算的流程（03 篇），能解释 KV cache 为什么省钱省时
- ❌ 不需要：手推反向传播、实现 attention 内核、复现 RLHF 训练——那是另一条职业路线

> 💡 费曼检验：向你的 Java 同事解释"为什么 LLM API 按 token 计费而不是按次"——因为每次请求的算力消耗与 token 数成正比（注意力 n² + 逐 token 生成），token 就是算力的计量单位。

## 【本节自测】

1. 四类翻车现场，各举一个你目前工作中可能踩的例子。
2. "模型记得上一轮对话吗？"——准确回答并说明记忆从哪来。
3. temperature=0 保证什么、不保证什么？
4. 思考 token 怎么计费？什么场景下它是成本大头？
5. 官方文档五句黑话，你能各翻译成一句"实际含义"吗？
6. 本笔记划定的"够用线"是什么？你现在的差距在哪？
