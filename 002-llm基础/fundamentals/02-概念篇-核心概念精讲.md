# 02 - 概念篇：核心概念精讲（12 张概念卡）

> 【本节问题】token 怎么切？注意力在"注意"什么？MoE 的"激活参数"是什么？KV cache 为什么是性能钥匙？思考 token 是什么、怎么计费？

![前向旅程](../diagrams/002-02-从Token到回答的前向旅程.svg)

> 每张卡：【一句话人话】→【生活类比】→【技术要点】→【常见坑】

## 卡 1：Token 与 Tokenizer（BPE）

- **一句话人话**：token 是模型世界的"积木块"，tokenizer 是把文本切碎成积木的机器。
- **类比**：乐高——任何句子都能拆成标准件，模型只认标准件不认原句。
- **技术要点**：主流用字节级 BPE（高频组合成块：`th`+`e`→`the`）；英文 1 token≈0.75 词，**中文 1 字≈0.6~1 token**；每个模型词表不同（GPT 系 ~100k，DeepSeek/Qwen 对中文优化更大词表）。
- **坑**：按"字数"估算成本和长度必错；用 tokenizer 工具（各家 playground）实测才准；生僻 emoji/乱码可能被切成一堆 token，又贵又差。

## 卡 2：Embedding（嵌入向量）

- **一句话人话**：把 token 翻译成一串数字（向量），让"意思"变成几何距离。
- **类比**：给每个词发一张"语义身份证"，身份证号相近=意思相近。
- **技术要点**：token → 一个 768~4096 维向量；训练后语义空间自动成型（国王-男人+女人≈女王）；**独立的 embedding 模型**（bge、text-embedding 系列）把整段文本变成向量，用于 RAG 检索（005 专题地基）。
- **坑**：embedding 相似≠事实正确——向量检索到"语义相近"的内容就停，别拿它替代事实校验。

## 卡 3：Attention（自注意力）

- **一句话人话**：每个 token 环顾全句，决定"我该重点看谁"。
- **类比**：读合同的你，看到"违约金"三个字会自动重点扫"百分之""上限""日"这些关联词——注意力就是模型的"重点扫描"。
- **技术要点**：每个 token 生成 Query（我在找什么）、Key（我是什么）、Value（我携带的信息）；用 Q·K 算相关度 → 加权求和 V。多头=多个视角同时扫（语法头/指代头/语义头）。**代价：n 个 token 两两看 n² 次**——这是长上下文贵的根源。
- **坑**：以为"模型在读全文"——它是"加权平均地看"，中间内容权重低时（lost in the middle）就会漏。

## 卡 4：Decoder-only 与自回归生成

- **一句话人话**：整个大模型就是一个"接龙机"：看前文 → 吐一个 token → 拼回去 → 再吐。
- **类比**：成语接龙高手，永远只能接着你最后一个字说。
- **技术要点**：2026 所有主流 LLM 都是 decoder-only 自回归；"回答"是一次接龙几十~几千次的产物；**没有先想好再输出**——流式输出（逐字蹦）就是它的真实工作方式。
- **坑**：以为模型"组织好了语言再说"——其实每一个字都是即时预测；理解这点才能理解延迟结构和流式 API 的设计。

## 卡 5：上下文窗口（Context Window）

- **一句话人话**：模型的"工作台"，一次推理能摊开的最大 token 数。
- **类比**：办公桌尺寸——桌上的文件都看得见，桌外的一概不知。
- **技术要点**：2026 旗舰标配 1M（GPT-5.6 系 400K~1M、Claude Opus 5 / Sonnet 5 1M、Gemini 3.1 Pro 1M、DeepSeek V4 1M、Llama 4 Scout 理论 10M）；**输入+输出共享窗口**；扩长技术：RoPE 位置编码、YaRN 插值（Qwen 原生 262K→可扩 1M）、DeepSeek V4 压缩稀疏注意力。
- **坑**：① 窗口大≠质量好（context rot：注意力预算被摊薄，中间内容召回率降）；② 部分厂商超阈值加价（Gemini >200K 翻倍、GPT-5.6 >272K ×2）。

## 卡 6：训练三部曲（预训练 → SFT → 对齐）

- **一句话人话**：先通读互联网（学知识），再上岗位培训班（学听话），最后绩效价值观考核（学规矩）。
- **类比**：学历 → 入职培训 → 绩效考核。
- **技术要点**：预训练（万亿 token 下一词预测，99% 算力）→ SFT（几万~百万条指令对）→ 对齐（RLHF/DPO/R1式RL）。详见 04 进阶篇。
- **坑**：混淆 Base 模型与 Chat 模型——拿 base 模型做对话会得到"续写你问题的文本"而不是回答。

## 卡 7：参数量、总参与激活参（MoE）

- **一句话人话**：总参=图书馆藏书量，激活参=每次实际翻开的册数；MoE 就是"巨大图书馆 + 智能取书员"。
- **类比**：医院全科医院（稠密=每个病人惊动所有科室）vs 分诊制（MoE=按病情叫号，只开 2~3 个科室）。
- **技术要点**：2026 主流全是 MoE——DeepSeek V4-Pro **1.6T 总参/49B 激活**、V4-Flash 284B/13B、Llama 4 Maverick 400B/17B、Qwen3.6-35B-**A3B**（A=激活 3B）；路由器（router）为每个 token 挑专家；好处：容量大 + 单 token 成本低。
- **坑**：把总参当推理成本（决定显存的是总参，决定单 token 算力的是激活参）；"A3B"这类命名看不懂就读不懂 2026 模型新闻。

## 卡 8：KV Cache

- **一句话人话**：把历史 token 的"Key/Value 索引卡"存下来，生成新词时只算新词、查旧卡。
- **类比**：看书时给每页贴便利贴摘要——不用每次从头重读全书。
- **技术要点**：Prefill 阶段（读 prompt）一次性并行建卡 → Decode 阶段每步只算新 token 的 K/V 追加；推理速度的数量级来源。**代价：占显存，与上下文长度成正比**——这也是 prompt caching 能省钱的物理基础（前缀的 KV 直接复用）。
- **坑**：以为 API 服务器"算完就扔"——KV 在请求期间驻留显存，这就是并发有限价、长上下文贵的原因。

## 卡 9：采样参数（temperature / top_p / top_k）

- **一句话人话**：控制模型掷骰子的"歪度"——是照标准答案抄，还是自由发挥。
- **类比**：temperature=0 的答题卡机器 vs 1.0 的即兴脱口秀演员。
- **技术要点**：温度缩放 logits → softmax → 按概率抽；top_p（核采样：只从累计概率 p 内的候选抽）、top_k（只从前 k 个抽）；抽取/分类/代码用 0~0.3，创作用 0.7+。**2026 特情：Claude 4.6+ 禁用手动采样参数（自适应取代），GPT-5 系用 reasoning_effort 管思考深度**。
- **坑**：temperature=0 ≠ 正确，只是可复现；参数解决不了提示词写得烂的问题。

## 卡 10：思考 token 与推理模型

- **一句话人话**：推理模型会在"正式回答前"先写一大段看不见的草稿（思考链），这段草稿也收输出费。
- **类比**：请了个顾问，报价包含"内部研究时间"——研究越久越贵也可能越准。
- **技术要点**：训练出来的能力（R1式 RL），不是提示词技巧；控制旋钮：GPT-5 `reasoning_effort`（low/medium/high）、Claude `effort` + 自适应思考、Qwen `enable_thinking`、DeepSeek V4-Flash/Pro 双型号；思考内容通常给摘要（`reasoning_content` / thinking 块）。**简单任务别用推理模型**（纯浪费）。
- **坑**：账单里思考 token 占输出 50%+ 很常见——Agent 长循环场景必须监控；对推理模型写"step by step"是画蛇添足。

## 卡 11：多模态（视觉/音频输入）

- **一句话人话**：给"文字接龙机"前面加一个翻译官——把图片/音频翻译成它认识的"token"。
- **类比**：接入一位手语翻译，聋哑人（图片）也能参会。
- **技术要点**：视觉编码器（ViT 系）把图切块成向量，与文本 token 同台进 attention（early fusion，Llama 4 的设计）；2026 旗舰全线支持图像输入（GPT-5.6、Claude、Gemini、Qwen3.6 带 vision 编码器）；DeepSeek V4 以文本见长，多模态另有布局。
- **坑**：图片 token 消耗远超想象（一张图≈几百~几千 token）；"看懂图"≠"看清小字"（表格截图识别仍有翻车率）。

## 卡 12：Prompt Caching 与计费结构

- **一句话人话**：相同的前缀（system+示例）第二次调用直接用现成的 KV，价格打 1~2 折。
- **类比**：健身房年卡——第一次办卡贵，之后每次进场几乎免费。
- **技术要点**：命中条件=前缀**逐字节相同**（所以"稳定内容在前、可变内容在后"是成本设计原则）；各家折扣：缓存命中约 0.1~0.2 倍计费（Claude Fable 5.1 甚至 97.5% off）；思考 token 按输出价；batch 半价。
- **坑**：把时间戳/随机 ID 放在 prompt 开头=缓存永久失效；误以为缓存跨用户共享（同租户同前缀才命中）。
