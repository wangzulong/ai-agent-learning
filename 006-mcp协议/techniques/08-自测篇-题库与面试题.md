# 08-自测篇：题库与面试题

> 【本节问题】① 概念、原理、实战、安全四层的掌握度怎么检验？② MCP 面试都考什么？③ 哪些是 2026 年的新考点？④ 答错的题该回哪一章补？

## 一、判断题（对/错+一句话理由）

1. MCP 取代了 function calling。 **错**——MCP 分发工具，最终仍翻译为模型 function calling；上下游关系。
2. `readOnlyHint: true` 保证工具无副作用。 **错**——Hint 是元数据提示，可伪造可变更，安全靠服务端校验。
3. stdio 传输中 Server 可以随意 print 调试日志。 **错**——stdout 只走协议消息，日志去 stderr。
4. resources 可以像 tools 一样由模型随时带参数调用。 **错**——resources 挂载权在应用侧，参数化查询用 tools（或模板资源+应用触发）。
5. 2026-07-28 版移除了 initialize 握手与 Mcp-Session-Id。 **对**——无状态化，版本/能力随 `_meta` 每请求携带。
6. sampling 是 Server 用自己的 LLM 生成内容。 **错**——是请求 **Host/客户端侧** 的 LLM，需用户审批，新版已弃用。
7. OAuth 体系中 MCP Server 是 Authorization Server。 **错**——是 Resource Server，授权委托独立 AS。

## 二、选择题

1. 三原语中由**用户**主动选择使用的是？ A.tools B.resources C.prompts D.notifications → **C**（tools=模型，resources=应用，prompts=用户）
2. 一次调用中"参数怎么传给工具"由什么定义？ A.annotations B.inputSchema(JSON Schema) C.instructions D.roots → **B**
3. 工具执行超时，协议层应？ A.返回 JSON-RPC error B.result.isError=true+错误文本 C.静默断连 D.重连再试 → **B**（业务错误交给模型自纠正）
4. 远程团队共享 CTRM 数据源应选？ A.stdio B.Streamable HTTP+OAuth C.两者均可 D.邮件 → **B**
5. 2025-06-18 版取代 HTTP+SSE 的是？ A.gRPC B.WebSocket C.Streamable HTTP D.MQTT → **C**
6. 防 confused deputy 的核心规范是？ A.RFC 8707 B.RFC 9728 C.OIDC Discovery D.PKCE → **A**（token audience 绑定；9728 是资源元数据发现）

## 三、简答题（含答题要点）

1. **画出/描述 MCP 三角色与 1:N 连接关系。** → Host 应用内多个 Client，各与一个 Server 保持 1:1 连接（图 006-02）。
2. **initialize 握手交换哪些信息，2026 新版变化？** → 协议版本+能力+身份；新版移除握手，随请求 `_meta` 携带并新增 server/discover（03 章 §5）。
3. **把"每日库存快照"与"按 SKU 查库存"分别做成什么原语，为什么？** → resource（只读快照、应用挂载、可缓存）与 tool（参数化、模型按需）——04 章判例表。
4. **写出 query_inventory 工具的 JSON Schema 要点。** → object 类型、properties 含 warehouse/sku、required 二者、description 写清单位与示例（05 章代码）。
5. **列举 tool poisoning / rug pull / confused deputy 及各一道防御。** → 描述注入→描述消毒+白名单；定义变更→hash 监控+批准缓存失效；凭据误用→RFC 8707+scope 分级（06 章）。
6. **为什么 2026-07-28 走无状态化？对企业部署意味着什么？** → 有状态会话阻碍负载均衡/扩容；无状态后任意实例可服务，免 Redis 与粘性路由（官方博客）。
7. **CTRM 项目中 function calling、MCP、A2A 各用在哪？** → 单应用原型用 function calling；跨客户端复用包 MCP Server；跨 Agent 协商用 A2A（07 章决策树）。

## 四、编码题（白板可写）

1. 用 FastMCP 写一个 `query_position` 工具：查某交易员持仓，含注解与参数校验。 → 参照 05 章 `@mcp.tool()` 模板：枚举参数、docstring、readOnlyHint=True。
2. 把 05 章 Server 从 stdio 改为远程 HTTP。 → `mcp.run(transport="streamable-http", ...)` + 客户端 `{"url": ...}`；补 OAuth 思路（06 章）。
3. 为上述 Server 设计显式句柄接口实现"多步询价篮子"。 → `create_basket→basket_id`、`add_item(basket_id,...)`、`price_basket(basket_id)`（04 章 §4）。

## 五、面试真题视角（2025~2026 高频）

| 考点 | 问法 | 题眼 |
|---|---|---|
| 定位 | "MCP 和 function calling 什么关系？" | 分发标准 vs 模型机制，翻译关系 |
| 架构 | "为什么 Client 要与 Server 1:1？" | 隔离凭据/能力/审计边界 |
| 原语 | "三种原语举三个 CTRM 例子" | tools 查库存 / resources 快照 / prompts 风控分析模板 |
| 安全 | "工具描述能信吗？" | 不全信：Hint 可伪造，描述可注入，hash+审批 |
| 演进 | "2026-07-28 变了什么？" | 无状态、MRTR、sampling/roots 弃用、CIMD |
| 工程 | "stdio 调试日志打哪？" | stderr（2025-11-25 起允许通用日志） |
| 生态 | "去哪发布/发现 MCP Server？" | 官方 Registry（2025-09-08 预览）+ server.json |
