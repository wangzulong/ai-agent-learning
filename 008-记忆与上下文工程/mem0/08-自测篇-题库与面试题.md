## L1 概念快答（10 题，每题 30 秒）

1. mem0 在 Agent 架构中扮演什么角色？它**不负责**什么？
2. mem0 的两个核心 API 是什么？各自在请求周期的什么位置调用？
3. 四层记忆是什么？分别挂什么作用域？
4. `user_id`、`agent_id`、`run_id` 哪个用来实现"自动过期"？
5. `infer=False` 的作用？
6. mem0 的提取/更新决策用四种操作，是哪四种？
7. 默认 LLM、embedding 模型、向量库是什么？
8. Graph Memory 在 OSS 里能用吗？
9. 提取阶段的 LLM 温度建议多少？
10. 哪三类数据绝对不能直接存进记忆层？

### 参考答案

1. 独立记忆层（记忆基础设施）；不负责编排/工具/路由等 Agent 框架职责。
2. `add()`（交互后写入）、`search()`（模型调用前检索）。
3. Conversation（本轮）/ Session（会话，run_id）/ User（长期，user_id）/ Org（全局共享）。
4. `run_id`。
5. 跳过 LLM 提取，原样存储文本。
6. ADD / UPDATE / DELETE / NOOP。
7. `gpt-5-mini`、`text-embedding-3-small`（1536 维）、本地 Qdrant（/tmp/qdrant）。
8. 不能。Graph Memory 是 Platform 功能；OSS 仅实体重合加成。
9. ≤ 0.2（确定性优先）。
10. 密钥/凭据、未脱敏 PII、其他敏感原文（先加密或哈希）。

## L2 原理理解（6 题，每题 2 分钟）

1. 完整描述 `add()` 的内部流程（至少 4 步），并说明异步摘要模块在其中的作用。
2. 为什么说 mem0 的自动提取是"增量式"的？这对生产系统意味着什么责任？
3. 检索的四路信号是什么？Platform 和 OSS 在此的差异？
4. 为什么 `score` 不适合当绝对阈值？正确的用法是什么？
5. 论文中 Mem0g 如何构建图、如何双路检索？它为什么时序推理强？
6. 全量上下文在 LoCoMo 上精度最高（72.9%），为什么生产不用？至少三个理由。
7. OSS 检索里，关键词和实体打分能不能往候选池里加新记忆？候选池实际多大？
8. OSS 里 SQLite 承担哪两件事？记忆元数据里 hash 和 lemma 各干什么用？

### 参考答案要点

1. 上下文查找（带最新摘要，防重复/辅助判断新旧）→ LLM 事实提取 → 去重+向量化 → 实体提取/入库；更新阶段按 top-s 相似记忆做 ADD/UPDATE/DELETE/NOOP；摘要后台异步刷新，保证提取时全局上下文最新。
2. 新矛盾事实（"搬到西雅图"）入库时旧事实（"住奥斯汀"）不会被静默改写 → 生产需显式 update/delete 或治理策略，否则新旧矛盾记忆并存会被同时召回。
3. 语义（向量）/ 关键词（BM25）/ 实体（重合或图加成）/ 时间（时间元数据 vs 查询时间意图）；Platform 四路全开且实体由内置图驱动，OSS 仅向量+可选 reranker+实体重合加成。
4. 它是四路信号融合分，不同 query 分布不同，无统一绝对标准；应按相对排序取 top-k，配合 reranker。
5. 两阶段 LLM 管线（实体抽取器→关系生成器）生成带类型三元组存 Neo4j；检索走"实体中心子图探索"+"三元组语义匹配"；结构显式保留时间与关系 → 时序推理强。
6. ① p95 延迟 17.12s vs 1.44s（差 91%）；② token 成本 ~26k/轮 vs ~7k（且每轮重付）；③ 上下文窗口容量硬约束，长对话装不下；④ 换来的精度差距小（~6 点）且 mem0 仍优于绝大多数记忆方案。
7. **不能**——只有 ANN 语义检索负责"出池"，实际召回 max(topK×4, 60) 条（topK=10 → 60 条）；BM25 与实体加分只在池内并行打分；语义(0~1)+关键词(0~1)+实体(0~0.5) 满分 2.5，求和后 ÷2.5 归一取 topK。
8. ① 增删改**变更日志**（对账/回放/溯源），② **最近 10 条消息**（给抽取器消解代词，如 it/he 指代）；hash 只用于**措辞完全相同**的去重；lemma（词形还原版本）供关键词（BM25）检索使用。

## L3 应用设计（4 题，动手/画图）

1. 设计"健身房会员助理"的记忆 schema：哪些信息进 user 层、哪些进 session 层、哪些不存？给出 metadata 设计。
2. 用户先后说"我对海鲜过敏"→ 半年后"我现在对海鲜不过敏了"。描述系统的完整行为链（提取→决策→检索→prompt）。
3. 你的 Agent 既要回答产品手册问题（500 页 PDF），又要记得每个客户的沟通历史。画出上下文组装流程图。
4. 把 06-生产篇的 chat() 改造为 LangGraph 节点图：节点怎么分、状态里放什么、写回放哪。

### 参考答案要点

1. user 层：会员等级、过敏史、器械偏好、教练偏好、伤病禁忌；session 层：本次约课流程状态（run_id）；不存：一次性寒暄、卡号原文（脱敏/加密后可存引用）。metadata：`{"club": "望京店", "member_tier": "gold"}`。
2. "对海鲜过敏"→ADD；半年后"不过敏了"→与新消息相似度最高的旧记忆参与更新决策→LLM 大概率 DELETE 或 UPDATE（改写为"曾对海鲜过敏，现已不再过敏"）；检索"他能吃什么"时时间信号偏向最新事实；prompt 记忆块呈现最新状态；关键：若 LLM 误判未清理，需业务侧提供显式修正入口。
3. 见 06 §4 图：query 同时进 RAG（手册向量检索）与 mem0.search（该客户 user_id 记忆）→ 两组结果分别标注来源注入 prompt（"产品资料：" / "客户背景："）→ LLM 作答 → 轮末值得记的沟通内容 add 回 mem0。
4. 节点：retrieve_memory → agent_reason（含工具循环）→ writeback_memory；State 含 user_id、messages、memories(检索结果)、final_answer；writeback 在 END 前执行，把新事实 add 回去；失败要容错（记忆挂了不能阻塞主对话）。

## L4 面试真题（6 题，含答题框架）

1. **"让你给现有客服 Agent 加长期记忆，你怎么设计？"**
   框架：先问场景（用户回访频率/会话长度）→ 选型（mem0 起步）→ 接入（Retrieve-Reason-Writeback 两接入点，增量改造）→ 治理（作用域/去重/压缩/合规）→ 评测（自建 QA 命中率 + 灰度对比）。
2. **"mem0 和 RAG 的区别？什么时候都要用？"**
   知识 vs 经历；静态 vs 动态；共性 vs 个性化；例子：电商客服（政策 RAG + 该用户订单偏好 mem0）。
3. **"记忆层怎么防止用户 A 看到用户 B 的信息？"**
   作用域强制 filters（code review 卡点）+ 租户级 collection 隔离 + 审计日志 + 权限层校验 user_id 归属。
4. **"mem0 论文里最打动你的数字是什么？怎么验证它适用于你的场景？"**
   例：p95 1.44s vs 17.12s（91%↓）+ token ~7k vs 26k（~73%↓），精度 -6 点 → 但要自建业务评测集复测，LoCoMo ≠ 业务分布。
5. **"用户说'我搬家了'，mem0 会怎么处理？这有什么风险？"**
   增量 ADD 新事实，旧地址保留；风险：检索同时召回新旧地址 → 依赖更新阶段 DELETE 决策（LLM 判断，非 100% 可靠）→ 强一致场景加版本化+显式修正。
6. **"如果让你自研一个记忆层，你会抄 mem0 哪几点、避免哪几点？"**
   抄：两阶段管线（提取+ADD/UPDATE/DELETE/NOOP 决策）、作用域模型、四路融合检索、异步摘要；避免/加强：OSS 图能力缺位、冲突检测可靠性、多模态、更激进的压缩与遗忘策略。
