## 1. 核心循环：Retrieve → Reason → Writeback

mem0 官方推荐的生产架构，**每个请求都跑同一个循环**，接入点只有两个（每步开头的检索、结尾的写回），可增量接入现有 Agent：

```
请求进入（user_id + query）
    │
    ▼
① Retrieve   mem0.search() → 取 top-k 记忆 → 注入 prompt 的记忆块
    │
    ▼
② Reason     LLM + 工具推理作答（多步推理中可再查 mem0）
    │
    ▼
③ Writeback  本轮值得记的内容 mem0.add()（新事实 / 更新既有记忆）
    │
    ▼
（后台）周期维护：摘要压缩、剪枝，保持记忆库信噪比
```

## 2. 完整集成示例（OpenAI + mem0，可直接改造成你的项目）

```python
import os
from openai import OpenAI
from mem0 import MemoryClient

llm_client = OpenAI(api_key=os.environ["OPENAI_API_KEY"])
mem_client = MemoryClient(api_key=os.environ["MEM0_API_KEY"])

AGENT_ID = "support-agent-v1"

def retrieve_memories(user_id: str, query: str, limit: int = 5):
    return mem_client.search(user_id=user_id, agent_id=AGENT_ID,
                             query=query, limit=limit)

def store_memory(user_id: str, text: str, metadata: dict | None = None):
    mem_client.add(user_id=user_id, agent_id=AGENT_ID,
                   text=text, metadata=metadata or {})

def build_prompt(user_message: str, memories: list[dict]) -> str:
    memory_block = ""
    if memories:
        joined = "\n".join(f"- {m['text']}" for m in memories)
        memory_block = f"Known user context:\n{joined}\n\n"
    system = ("You are a helpful support agent. Use the known user context "
              "when relevant, and avoid asking for information already present there.")
    return f"{system}\n\n{memory_block}User: {user_message}\nAssistant:"

def chat(user_id: str, user_message: str) -> str:
    memories = retrieve_memories(user_id, user_message)          # ①
    prompt = build_prompt(user_message, memories)
    resp = llm_client.chat.completions.create(
        model="gpt-4o-mini",
        messages=[{"role": "user", "content": prompt}],
        temperature=0.2,
    )
    answer = resp.choices[0].message.content                     # ②
    store_memory(user_id, f"User said: {user_message}")          # ③
    return answer
```

**工程细节**：
- 记忆块要有明确包裹（`Known user context:`）+ system 指示"优先用已知上下文、别重复追问"
- Writeback 不是无脑全存——挑"值得复用的"（用户偏好、决策、新事实），或交给 add 的提取机制把关

## 3. 主流框架集成模式

| 框架 | 接法 | 思路 |
|---|---|---|
| **OpenAI Agents SDK / 自研循环** | 如上：工具化两个函数 | search 作为上下文注入，add 在轮末调用 |
| **LangChain / LangGraph** | 把 mem0 包成一个 **Tool** 或 Graph 节点 | 检索节点放在 LLM 节点前；写回节点放在结束前 |
| **CrewAI** | 官方内置 mem0 集成 | Crew 配置里直接开 memory backend |
| **mem0 Platform MCP** | 走 MCP 协议 | 让任何支持 MCP 的客户端（如 Claude、Cursor 类工具）直接获得记忆能力 |

> 设计原则（费曼式）：**记忆层是"水电煤"，不是"主角"**。它应该被任何框架以最低成本取用，而不是绑架你的架构。

## 4. 与 RAG 的共存架构

| 维度 | RAG | 记忆层（mem0） |
|---|---|---|
| 内容 | 静态知识：文档、手册、政策 | 动态经历：用户事实、会话沉淀 |
| 数据来源 | 语料库，人工/批处理维护 | 用户交互自动沉淀 |
| 更新频率 | 低（内容版本化） | 高（每次交互都可能写） |
| 个性化 | 无（对所有人一样） | 有（按 user/agent 隔离） |
| 典型问题 | "退货政策是什么" | "我上次买的什么尺码" |

**生产组合拳**：

```
用户提问 ──┬─→ RAG 检索（知识片段）─────────┐
           └─→ mem0.search（用户记忆）──────┤
                                            ▼
                              LLM 综合两类上下文作答
```

两者互补不替代：RAG 答"世界是什么样"，记忆层答"**这个用户**经历了什么"。

## 5. 成本优化清单

| 手段 | 说明 |
|---|---|
| 控制注入量 | `limit` 取 3~5 条高相关记忆即可，宁缺毋滥 |
| 记忆压缩 | 定期把旧记忆归并/摘要（Platform 的 Memory Compression Engine 自动做；OSS 自建 cron + LLM 压缩） |
| 分层存储 | 一次性信息留在会话层（run_id），别污染长期库 |
| 检索裁剪 | reranker `top_k` 10~20；无关记忆不进 prompt |
| 缓存 | 高频 query 的检索结果短 TTL 缓存 |

## 6. 安全与合规（红线清单）

- 🚫 **绝不**存：密钥、原始凭据、未脱敏 PII（身份证号、卡号）——**记忆层天生为"可检索"而生**，存进去=放进一个必然被查出来的地方
- ✅ 敏感值先**加密或哈希**再入库；展示层脱敏
- ✅ 用户对"被记住"要有知情与清除渠道（对应 GDPR 删除权 → 提供 `delete_all` 能力）
- ✅ 合规背书：mem0 Platform 有 SOC 2 (Type 1)、HIPAA、GDPR；支持 BYOK、审计日志（每次读写可追溯"谁在何时写了什么"）
- ✅ 多租户隔离：显式 `collection_name` / metadata 租户标 + **所有查询强制带 filters**

## 7. 评测：上线前先量，上线后持续量

| 评测对象 | 方法 |
|---|---|
| 检索质量 | 自建 20~50 条 QA：已知某用户记忆，问对应问题，看 top-3 命中率 |
| 提取质量 | 抽 30 段真实对话人工核对：该记的记了吗？不该记的混进来吗？ |
| 端到端 | 对比"有记忆 vs 无记忆"两版的回答满意度（LLM-as-a-Judge 或人工） |
| 行业基准 | LoCoMo（长对话记忆）、LongMemEval、BEAM（官方宣称三项均做了 benchmark） |

## 8. 上线检查清单（Copy 即用）
