# 08 - 自测篇：题库与面试题

> 【本节问题】① 概念是不是真懂了？② 旅程图能不能默画？③ 工程决策能不能拍板？④ 面试怎么答显功力？

> 用法：遮住要点自测；错题回对应篇章；按文末间隔重复计划复习。

---

## L1 概念层（回 02 概念篇）

1. 模型在工具调用中"执行"工具吗？
   > 要点：不。模型只生成调用意图（名字+JSON 参数），执行永远在客户端代码层。
2. tools 定义每次请求都发吗？为什么？
   > 要点：是。工具定义就是上下文的一部分（prompt），模型无状态记忆；稳定前缀吃缓存（002 篇）。
3. 并行工具调用的配对键是什么？（三家分别）
   > 要点：OpenAI call_id / Anthropic tool_use_id / Gemini 按 name 配 response。
4. strict mode 解决什么、不解决什么？
   > 要点：解决"参数符合 schema"（约束解码）；不解决"值语义正确"（数量对不对还得业务校验）。
5. tool_choice 的用途举一例。
   > 要点：强制走某工具——如邮件分类后强制先调 extract_email_elements，杜绝模型自由发挥。

## L2 原理层（回 03 原理篇）

6. 默画一次工具调用旅程六步。
   > 要点：请求带 tools → 模型输出 tool_calls → 客户端校验执行 → 结果回填 → 模型续答或再调 → 无调用则终答。
7. 为什么"参数幻觉"是概率系统的必然？两个治理抓手？
   > 要点：模型按分布生成 token；抓手=schema 硬约束（enum/strict）+ 代码层业务校验。
8. 工具描述怎么影响注意力分配？
   > 要点：description 是模型选工具的最强信号；写"何时用/何时不用"= 给注意力画边界（001 篇原理）。

## L3 工程设计层（回 04/05/06 篇）

9. 设计 `create_price_apply` 工具的完整清单（定义、幂等、权限、评估）。
   > 要点：扁平参数+enum+required 精准；request_id 幂等去重；挂起人工确认；审计表 100% 落库；评估集含误调样本。
10. 工具返回 30k token 怎么改？分两步说。
    > 要点：①给模型的返回做摘要投影（top N/字段裁剪/分页 offset）；②成本+注意力稀释双重动机（context rot）。
11. 传输错误和语义错误的处理分界？
    > 要点：换个时间重试会不会好——会：代码层指数退避+幂等；不会：错误文本回填模型自纠；三次不自纠转人工。
12. 点价 agent 出现"高频调 query_futures_price 但参数总错"，排查顺序？
    > 要点：参数描述缺单位格式 → enum 缺失 → 返回错误信息不可自纠 → 上下文里口径被稀释（重锚）→ 榜单级模型能力问题（换模型）。

## L4 综合题（面试压轴）

13. **设计题**：CTRM 要把 12 个内部服务开放给 agent 使用，工具面怎么设计？
    > 要点：读写分级（9 读 3 写）；命名空间分组；写操作全部幂等+人工确认；动态注入按任务阶段挂子集；配 trace 与评估集；预留 MCP 分发（006 联动）。
14. **辩论题**："模型越来越强，工具描述随便写写也行了吧？"
    > 要点：模型升级降低的是"措辞敏感度"不是"信息需求"；描述里缺失的语义（何时不用/失败语义/单位）换什么模型都会用默认行为补；正确姿势=描述进版本管理+评估回归，模型升级只降 prompt 微调成本。
