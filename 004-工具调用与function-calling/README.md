# 004 - 工具调用与 Function Calling 学习专题

> 这是 AI Agent 学习路线的"手脚层"。**Agent 与聊天机器人的本质区别，就是会不会用工具**——001 教会模型"怎么想"，003 教会模型"怎么循环"，本专题教会模型"怎么动手"。你将搞懂：为什么模型永远不执行工具、一次调用在四条泳道间怎么流动、工具描述怎么写才让模型"指哪打哪"，以及三家 API 的差异怎么影响你的架构。

## 🧭 一句话定位

**工具调用 = 模型生成"调用意图"（JSON），你的代码执行真实动作，再把结果喂回去继续生成。**

这句话里有三个角色：模型（只出意图）、客户端（真干活）、外部系统（被调用）。全文 11 篇笔记都在展开这半句话。

## 🔗 与其他专题的关系

- **001-prompt工程**：工具的 description 就是一份微型提示词（描述工程 = Prompt 工程的子问题）；06 生产篇的工具层注入防御直接复用 001 的"不可信输入隔离"原则。
- **003-agent原理与架构**：工具调用是 Agent 循环里的 **Action** 步骤。003 讲整个循环（感知→思考→行动），本专题把 Action 这一步拆到螺栓级。读完本篇再回去看 003，"循环"二字会立体起来。
- **006-MCP 专题（埋钩子）**：本篇的四个 CTRM 工具是你自己写、自己维护的"私有工具"。当工具要多系统共享、要多 Agent 复用时，就需要 MCP 把"工具分发"标准化——006 专题见。
- **002-llm基础**：03 原理篇的"采样视角"解释了为什么工具定义能影响模型行为——因为它就是上下文 token 的一部分（呼应 002 卡 3/卡 4）。

## ⚡ 三个先记住的事实（读完 11 篇你会反复验证它们）

1. **模型不执行工具，只生成调用意图**——一切安全与架构设计的出发点。
2. **工具定义是 prompt 的一部分，按输入 token 计费**——工具不是免费的，描述越啰嗦账单越疼。
3. **错误信息是给模型读的**——写得像人能看懂，模型才能自愈重试；写得像日志，模型只会死循环。
