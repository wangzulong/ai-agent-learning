## B. 场景题（实操，给思路要点）

1. **你负责 CTRM 的合同评审自动化，领导要求"全部 Agent 化"。你怎么裁？**
   要点：先分拣——规则可穷举的步骤（金额换算、日期计算、状态流转）写代码；只有多视角判断环节（要素抽取、风险认定、价格评估）上 Agent；给出单 Agent 先行的证据再谈拆分。
2. **三个 Worker 的交付物字段名对不上，评审意见打架。排查与根治？**
   要点：trace 回放定位第一个口径漂移点；根治 = 交付物 Schema 前置 + 自动校验打回 + 公共事实字典（06 篇失败模式①）。
3. **风控员和定价员的结论冲突（价格没问题但风险高）。主管怎么汇总？**
   要点：这不是 bug 是交叉验证的价值；主管规则先行（风险高 → 评审结论降级为"暂缓"，无论定价如何），LLM 只做解释而非裁决；裁决规则要写进代码而不是指望模型。
4. **上线一周发现 Token 成本是预估的 3 倍。四步排查？**
   要点：按 trace 归因到 Worker 粒度 → 查是否有人传完整历史而非结构化产物 → 查模型分级是否失效 → 补预算护栏 + 抽样重估基线（06 篇失败模式④）。
5. **业务方要求接入外部供应商的报价 Agent。用什么协议接入，为什么不用 MCP 工具？**
   要点：对方是自主 Agent、任务长、可能中途澄清 → A2A；先拉 Agent Card 验能力与鉴权（v1.0 JWS 签名卡）；MCP 工具适合固定输入输出的一次性调用（04 篇灰区判断）。
6. **评审小组要把"主管拆解"从写死改为 LLM 动态拆解（L1→L2），风险与前置条件？**
   要点：风险 = 拆解错误传导全链；前置 = 主管输出子任务 JSON 也过 Schema 校验 + 全局轮次上限 + 打回预算，再灰度放量（03/06 篇）。

## C. 面试题（如实战追问，答出"结构 + 依据"才算过关)

1. **"为什么要多 Agent？单 Agent 加长上下文不行吗？"**
   参考结构：结构性天花板（装不下/选不清/串行/混杂）→ context rot 证据（003）→ 但先亮代价（15×）→ 给裁定信号清单。踩坑警告：只吹好处不提 15 倍与"能单就单"，会被认为没上过生产。
2. **"设计一个点价评审的多 Agent 系统，现场画架构。"**
   参考结构：星型拓扑（配 007-06）→ 主管/抽取/风控/定价职责与工具边界 → handoff 四件套 → Schema 校验打回 → 轮次上限与 HITL → trace 与预算。加分点：主动说"拆解逻辑写死（L1）降低不确定性"。
3. **"A2A 和 MCP 什么关系？有了 MCP 为什么还要 A2A？"**
   参考结构：两层互补（连工具 vs 连 Agent）→ 工作单元差异（单次调用 vs Task 状态机）→ 暴露差异（显式 schema vs 不透明）→ 治理现状（2026-08 起同属 AAIF）→ 灰区判断（自主性/多轮/长任务选 A2A）。加分点：提到 MCP 实验性 tasks 原语但不混淆本质。
4. **"多 Agent 系统 Token 为什么放大 15 倍？怎么控？"**
   参考结构：放大来源（Worker 重复读背景/交接载荷/编排消耗/并行）→ 四个防御（预算护栏/模型分级/抽样试跑/按价值分级）→ Anthropic 出处。
5. **"Worker 之间该共享多少上下文？"**
   参考结构：默认最小集合（隔离收益）→ 共享的只有公共事实字典与交付物 → 反例（强耦合任务隔离反而制造断层）→ 结论：按"事实类型"分层而不是"全共享或全私有"。
6. **"你的多 Agent 上线后卡死了，怎么建可观测？"**
   参考结构：trace_id 全链路 → 消息级流水（角色/轮次/耗时/Token）→ LangSmith/Langfuse 平台化 → 回放定位口径漂移点 → 把修复固化回 Schema/提示词。
