# 007 · 多 Agent 系统（Multi-Agent Systems）

> 一句话定位：**当一个 Agent 装不下、跑不动、管不清的时候，把活拆给一群角色化的 Agent——但先算清楚 15 倍 Token 的账。**

## 这章讲什么

单 Agent 是"一个全栈工程师硬扛所有活"；多 Agent 是"组建一个小团队"。本章讲清三件事：

1. **什么时候该拆**：单 Agent 的四大天花板（上下文装不下、工具太多、串行慢、Prompt 膨胀），以及**什么时候不该拆**（Anthropic 观点：能单就单，多 Agent 是双刃剑）；
2. **拆了怎么协作**：角色、编排者、通信、handoff、拓扑（星型/流水线/层级/网状）、A2A 协议；
3. **怎么不翻车**：失败模式（谁也不认账、信息丢失、循环踢皮球、成本失控）与防御。

**贯穿案例：点价评审小组**——来自中基集团 CTRM 贸易系统的真实场景。主管 Agent 接到一笔点价单的评审任务，拆解后并行派给三个 Worker（**抽取员**抽合同要素、**风控员**核风险、**定价员**验价格），收齐三份结构化交付物后交叉核对，汇总出具评审意见。全程对应 Java 开发者熟悉的概念：orchestrator ≈ 工作流引擎，handoff ≈ 工单转派，Schema ≈ DTO 契约，并行 ≈ `CompletableFuture.allOf`。

## 与其他章节的衔接

| 章节 | 衔接点 |
|---|---|
| **003-上下文工程** | 多 Agent 的核心收益是**上下文隔离**：每个 SubAgent 只带自己需要的上下文。003 讲 context rot（上下文腐烂）——信息越多注意力越稀释，多 Agent 正是对症的手术刀。03-原理篇会反复回指。 |
| **004-单agent设计模式** | 多 Agent 不是替代而是升级：ReAct、Plan-and-Execute 在每个 SubAgent 内部照用不误。先掌握单 Agent 的工具循环，再看本章如何把多个循环编排起来。 |
| **006-MCP协议** | MCP 是 Agent 连接**工具/数据**的协议（纵向）；A2A 是 Agent 连接 **Agent** 的协议（横向）。006 吃透 MCP 的 Server/Client 模型，本章的 A2A 一节会非常顺。 |
| **009-框架实战** | 本章 05 实战篇手写"无框架多 Agent"，看透本质；07 对比篇给出框架选型决策树，具体框架 API 细节与完整项目见 009。 |
