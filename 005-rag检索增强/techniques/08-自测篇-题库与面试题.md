# 08-自测篇：题库与面试题

> 【本节问题】① 概念题我能不能秒答？② 原理题能不能讲清"为什么"？③ 工程题能不能落到 CTRM 场景？④ 面试大题怎么组织出结构化回答？

**使用说明**：先遮住要点自测；答错回到对应篇目（题后括号标注）。面试大题在文末，用"总—分—例"结构作答。

## 一、概念判断题（对/错并说理由）

**1. RAG 微调了大模型的参数，所以知识能更新。（ ）** [00 背景篇]
要点：错。RAG 不动参数，知识在外部索引里；"改数据不改模型"正是其卖点。

**2. chunk 越大，召回越准。（ ）** [02 概念篇]
要点：错。大块 embedding 语义被稀释，相似度变糊；小块检索大块生成（父子块）才是解。

**3. 有了百万 token 上下文，RAG 就过时了。（ ）** [01 问题篇]
要点：错。成本×频次、注意力稀释、新鲜度、权限四关过不去；权限是硬门槛。

**4. 余弦相似度和内积在任何情况下等价。（ ）** [02 概念篇]
要点：错。向量归一化后才等价。

**5. rerank 模型可以像 embedding 一样预先算好存库。（ ）** [02 概念篇]
要点：错。cross-encoder 输入是 (query, doc) 对，query 到了才能算。

## 二、原理简答题

**6. 画出/口述 RAG 两条管道的全部环节。** [03 原理篇]
要点：索引=加载→清洗→分块→向量化→入库；查询=改写→召回（双路）→融合（RRF）→重排→打包→生成；能报出每步一个失败模式加分。

**7. BM25 和向量检索各自的强项？为什么要融合？** [03 原理篇]
要点：BM25 强在精确匹配（编号/品名/数值），向量强在语义泛化（同义改写）；单路都有盲区，融合互补。

**8. RRF 公式及其相对分数加权的优势？** [03 原理篇]
要点：score=Σ1/(k+rank)，k≈60；只用名次，免疫两路分数量纲差异。

**9. 父子块检索为什么能同时提升检索精度和回答质量？** [04 进阶篇]
要点：小块 embedding 聚焦→检索准；命中后返回父块→生成上下文足。

**10. GraphRAG 解决向量 RAG 的什么盲区？LazyGraphRAG 破了什么局？** [04 进阶篇]
要点：跨文档多跳关系推理（答案不在单块内）；LazyGraphRAG 把 LLM 摘要推迟到查询时，索引成本降至全量版约 0.1%（Microsoft Research Blog）。

## 三、工程实践题

**11. 检索回来的块里总出现"第 3 页 共 45 页"，怎么办？** [03 原理篇]
要点：清洗环节按文档类型去页眉页脚；这是"幽灵句"污染 top-k。

**12. 用户问"升贴水怎么算"，答出来的公式是旧版规则。根因与修复？** [06 生产篇]
要点：新旧版本并存；铁律=同一文档仅一个生效版本，增量更新+淘汰旧块。

**13. 多租户下 A 租户用户偶尔搜到 B 租户的合同条款，怎么排查？** [06 生产篇]
要点：查权限过滤层级——入库 schema 校验权限字段→检索前 where 过滤；绝不能只做检索后过滤（top-k 缺口+中间态泄露）。

**14. RAGAS 评估 faithfulness 低、context recall 高，修哪？** [06 生产篇]
要点：资料给了但答案越界——修生成端：接地模板、低 temperature、允许拒答。

**15. embedding 调用费用翻倍，三个最可能的省钱动作？** [06 生产篇]
要点：query 向量缓存、批处理、（若换 API）选低价模型/私有化；rerank 候选封顶管的是重排费用。

## 四、场景设计题

**16. 为 CTRM 设计知识库的分块方案（合同模板/规则手册/历史案例三类）。** [02/03]
要点：合同按"第X条"自定义分隔符递归切；规则手册含表格→表整体成块+父子块；案例按单条案例切并带时间/品种元数据；统一存元数据（dept/tenant/版本/生效日）。

**17. 业务方要求"答案必须可追溯到条款原文"，怎么落地？** [02/05]
要点：入库时保留章节/页码元数据；打包时来源前缀编号；生成模板强制 [资料n] 引用 + 拒答；前端把引用渲染成可点击跳转。

**18. 领导问"直接把知识库塞给模型不是更快吗"，给出三分钟回应。** [01]
要点：成本（每次查询重复付费×高频）、Lost in the Middle（长≠记得住）、新鲜度（数据操作 vs 发布动作）、权限（唯一解）四点+结论"小而私低频可直塞，企业库必须 RAG"。

## 五、面试大题

**19.（大题）"设计一个支持多租户的企业知识库 RAG 系统，重点讲权限与质量保障。"**
参考框架：
- 总：两条管道 + 权限贯穿设计原则；
- 分1 架构：pgvector + BM25 双路 → RRF → rerank（top50 封顶）→ 接地生成；
- 分2 权限：入库 schema 校验租户/部门字段 → 检索前 where 过滤（对比检索后过滤两大问题）→ 生成端无权限内容零出现；
- 分3 质量：RAGAS 四指标定位口诀、评估集含拒答题、版本治理（单一生效版本）、 Lost in the Middle 对抗（重要内容放开头结尾）；
- 收尾：成本三件套（向量缓存/rerank 封顶/答案缓存）与演进路线（先 Naive → 加重排 → 按需 GraphRAG/Agentic）。

**20.（大题）"RAG、长上下文、微调怎么选？给一个你项目的选型过程。"**
参考框架：
- 总：三者改的对象不同——数据/输入/权重，常组合非互斥；
- 分：决策表七维度（更新频率/成本曲线/权限/审计/风格/知识类型/频次）；
- 例：CTRM 例——规则问答走 RAG（权限+新鲜度），单合同深读直塞长上下文，合同起草语气微调；实时数值一律路由业务 API 不进任何方案。

## 【本节自测】

1. **面试答 RAG 大题的结构模板是什么？**
   要点："总—分—例"：先一句话给结论/架构，再分维度展开，最后落到具体项目例子（CTRM）。
2. **被问"RAG 和微调怎么选"，第一句应该说什么？**
   要点：先说"两者改的对象不同——RAG 改数据、微调改权重，常组合而非互斥"，再展开决策表。
3. **面试官追问"你的系统幻觉怎么办"，答题顺序？**
   要点：先归因（召回缺失/版本冲突/模型越界三层），再逐层给解法，不要直接背"加 rerank"。
4. **被质疑"向量库选型为什么不用 Milvus"，怎么回应？**
   要点：按规模与运维成本说理（百万级 pgvector 够用、零新增运维），并给出升舱触发条件——展示的是决策过程而非站队。
5. **答不上来的面试题，最优策略？**
   要点：如实说边界+给推理路径（"这个我没实际用过，但类比 X 我会这么推"）；企业场景同理——允许拒答优于编造。
