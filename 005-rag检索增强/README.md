## 专题定位

RAG（Retrieval-Augmented Generation，检索增强生成）是所有企业级 LLM 应用中**工程密度最高、回报最确定**的一块：不改模型权重，靠"外挂知识库 + 检索"解决大模型的知识陈旧、私有知识缺失、幻觉三大痛点。

本专题以 **CTRM 贸易知识库问答** 为贯穿案例：把合同模板、业务规则、操作手册、历史点价案例四类资产建成知识库，回答"点价流程是什么""升贴水怎么算"这类问题。你不需要换技术栈——文中的向量库、权限过滤、评估等概念都可以映射回你熟悉的 Java 11 + Vue 2.7 + MySQL 工程经验。

## 与其他专题的衔接

| 衔接点 | 说明 |
|---|---|
| **001（LLM 基础）** | RAG 的"G"端是 LLM：上下文窗口、token 计费、temperature 这些概念在 001 铺垫；本专题的 context packing 就是在为 001 讲的窗口预算做工程化 |
| **002（Prompt 工程）** | RAG 的"引用接地"本质是 prompt 模板设计：答案必须标注 [来源 n]、答不上要拒答，这套模板范式在 002 展开 |
| **003（Agent 架构）** | **最强关联**：04 进阶篇的 Agentic RAG 把"检索"降级为 agent 的一个工具，由 agent 在 ReAct 循环中决定何时查、查什么、查几轮——工具循环协议见 003 |
| **008（工程化/生态）** | 06 生产篇的评估体系、缓存、成本监控是通用工程话题，可带着 RAG 这一具体场景回到 008 的工程化框架中复用 |

## 贯穿案例：CTRM 贸易知识库问答

| 知识资产 | 示例问题 | 检索难点 |
|---|---|---|
| 合同模板 | "背靠背合同的价格调整条款怎么写？" | 条款编号与正文必须同块，切块不能切断 |
| 业务规则 | "升贴水怎么算？" | 规则文档常有表格，需要清洗与结构保留 |
| 操作手册 | "点价流程是什么？" | 步骤类长文，适合父子块（小块检索大块作答） |
| 历史点价案例 | "2025 年三季度铜点价有没有在贴水扩大时锁价的案例？" | 时效性 + 数值精确匹配 → BM25 强项，混合检索价值大 |
