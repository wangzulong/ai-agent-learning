# 08 · 自测篇：题库与面试题

> 【本节问题】① 009 全章的概念能不能闭卷复述？② 面试官会怎么问框架问题？③ 实操题能不能独立完成？④ 哪些高频坑必须形成肌肉记忆？

用法：先遮住要点自答，再核对。分四组：概念题 / 原理题 / 实操题 / 面试实战题。

## A. 概念题（对照 02 概念篇）

**A1. StateGraph 为什么允许环？DAG 不行吗？**
要点：LLM 步数不定（工具可能调多轮），需循环直到终止条件；DAG 只能单向无环，表达不了 ReAct 迭代。

**A2. 节点返回 dict 的语义？reducer 干什么？**
要点：返回增量 patch；reducer 定义同字段并发/多次写入如何合并（如 `Annotated[list, add]` 追加），默认覆盖。

**A3. 条件边 vs Command(goto+update) 的选择？**
要点：条件边=图上显式分支（全局可审查，通用）；Command=节点内打包"更新+跳转"（分支与节点强耦合时）。

**A4. checkpointer 和 interrupt 为什么是搭档？**
要点：interrupt 挂起后进程可死、可隔天恢复，靠的是状态已落盘；恢复=读档+续跑。

**A5. handoff 与 subgraph 的区别？**
要点：handoff=运行时控制权移交（多 Agent 转接）；subgraph=编译期模块化复用（图当节点）。可组合：主管图用条件边实现 handoff 到子图。

**A6. 短期记忆/长期记忆实现件？**
要点：短期=thread 内 state 历史（checkpointer 自动）；长期=Store（namespace+key，跨 thread）。

**A7. trace/span 与 LangGraph 的天然对应？**
要点：一次图执行=trace；一个节点执行=span；thread_id 做检索键。

**A8. streaming 三粒度与生产最常用？**
要点：token（打字机）/事件 updates（进度条）/状态；生产最常用 updates。

## B. 原理题（对照 03 原理篇）

**B1. 五层共性件？哪层最分野？**
要点：状态容器/调度循环/工具运行时/持久化钩子/可观测钩子；持久化层最分野（决定 HITL 与恢复能力）。

**B2. 003 手写循环的哪些件在框架里是"能力从无到有"？**
要点：人工确认（input→interrupt）、断点恢复（无→checkpointer）、全链路日志（print→trace）；状态/路由/工具只是"表达力升级"。

**B3. "换框架五问"？**
要点：状态怎么定义、循环谁控制、工具怎么注册、持久化在哪、埋点在哪。

**B4. MCP 对应哪层共性件，2026 现状？**
要点：工具运行时；Spring AI 1.1+、LangChain4j 1.x 原生支持，事实标准。

## C. 实操题（对照 05 实战篇）

**C1. 手写：定义 PricingState 并让 audit_log 支持并行安全追加。**
要点：`audit_log: Annotated[list[str], add]`。

**C2. 手写：给"生成建议单"节点加人审——价格越限价带才挂起，常规单自动过。**
要点：节点内 `if not within_band: review = interrupt({...})`；恢复 `Command(resume={...})`。

**C3. 手写：编译图并支持崩溃恢复与流式进度。**
要点：`compile(checkpointer=SqliteSaver.from_conn_string(...))`；`graph.stream(..., stream_mode="updates")`。

**C4. 排错：同一 thread_id 二次 invoke 报"无待恢复中断"？**
要点：一次中断只消费一次 resume；或该 thread 已跑完，新任务应开新 thread。

**C5. 排错：并行节点写 extracted 字段互相覆盖？**
要点：给字段声明 reducer；或重新设计避免并行写同字段。

**C6. 迁移：把 05 的 SqliteSaver 换成生产可用后端。**
要点：PostgresSaver；MySQL 无官方 checkpointer（截至 2026-09 未见权威披露），可自实现 BaseCheckpointSaver 或换 Postgres。

## D. 面试实战题

**D1. 面试官："你说用了 LangGraph，它解决了你什么问题？"（考察：是否真懂框架价值分层）**
参考答：三层——样板收敛是顺带；控制流声明化（条件边上图）是效率；最关键的是 checkpointer+interrupt 给了"挂起数天的人审 + 崩溃恢复"，这在手写版里等价于自建消息队列+状态库+恢复协议。

**D2. 面试官："LangGraph 和 CrewAI 怎么选？"（考察：抽象模型差异）**
参考答：LangGraph 显式状态图、可控可审计、学习陡；CrewAI 角色隐喻、起步快、持久化弱。社区常见路径：CrewAI 原型 → 可靠性/审计要求出现后迁 LangGraph。

**D3. 面试官："Java 团队怎么做带人工审批的 Agent？"（考察：JVM 生态短板认知）**
参考答：两条路——①Spring AI + Spring Statemachine 自建挂起状态行（把 HITL 建模成业务状态机）；②编排层 Python LangGraph 服务化，Java 走 REST/SSE。当前 JVM 框架无内置 checkpointer/interrupt（2026-07 对比文），重状态场景不硬扛。

**D4. 面试官："interrupt 的恢复协议说说？"（考察：细节深度）**
参考答：中断时状态已写 checkpoint；恢复带同一 thread_id invoke `Command(resume=payload)`；payload 成为节点内 interrupt() 的返回值；进程可跨机器、跨时间恢复。

**D5. 面试官："Agent 上线后怎么排查'昨天有一单建议单价格离谱'？"（考察：可观测体系）**
参考答：报盘单号=thread_id 检索 trace → 看 extract 节点输入输出（抽取错？）→ 看查价 span（行情源错？）→ 看 draft_proposal 的限价带判断（规则错？）→ time-travel 分叉重放验证修复。

**D6. 面试官："为什么 2026 年框架数量收敛了？"（考察：行业视野）**
参考答：1.0 里程碑密集（LangGraph/LangChain 2025-10、MAF 2026-04、Spring AI 2025-05），AutoGen 进入维护模式，格局沉淀为图编排/官方 SDK/角色协作/Java 生态四个梯队；加上 MCP/A2A 标准化降低了框架间差异。
