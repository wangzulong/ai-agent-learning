# 01 · 问题篇：框架到底帮你省了什么

> 【本节问题】① 003 篇手写的点价 Agent 已经能跑，为什么还要上框架？② 框架帮你省的到底是什么——代码量、正确性还是可维护性？③ 哪些事框架永远帮不了你？④ Java 工程师用什么类比理解"框架换走的是控制权"？

## 1. 先复盘 003 篇：手写点价 Agent 的工程件清单

003 篇用纯 Python 手写了点价 Agent：路由 → 抽取 → 查库存 → 查价 → 生成建议单 → 人工确认。把代码里的"工程件"拆出来数一数：

| 手写工程件 | 003 篇实现方式 | 痛点 |
|---|---|---|
| 状态传递 | Python dict 层层传参 | 字段一多就乱，无类型校验 |
| 路由分发 | if/elif 判断意图 | 规则散落，加一类报盘改三处 |
| 工具调用 | 手写函数 + 手拼 JSON prompt | schema 无校验，异常各写各的 |
| 循环上限 | `while step < MAX_STEPS` | 忘写就死循环烧 token |
| 人工确认 | `input()` 阻塞 | 进程挂住、重启全丢 |
| 日志 | print / logging 手埋 | 链路不连贯，事后查不了 |
| 失败恢复 | 没有 | 崩了从头再来 |

手写版**能跑，但每一步都是你欠的债**。框架的本质：把这 7 件债变成官方还过的债。

## 2. 框架帮你省的三层东西

**【一句话人话】** 框架省的不是"代码行数"，省的是"你没想到的坏情况"。

**【生活类比】** 手写 Agent 像自己装装修水电——能亮灯能出水；用框架像买精装房——水电验收标准是行业写好的，你踩不到"零线火线接反"这种坑。

### 第一层：省样板代码（最薄的一层）

工具注册带 schema 校验、消息拼装、流式输出管道。这一层价值有限——003 篇证明你手写也就半天。**只冲这层上框架，不值。**

### 第二层：省控制流的正确性（中间层）

路由、分支、并行、循环上限、错误转移——框架把这些变成"声明"而不是"代码"。比如 LangGraph 里条件边是图上一条线，视觉可查、改动局部化；手写版是散在 router 函数里的 if。CTRM 对照：**这就是把业务流程从散装 if 升级成 BPMN 流程图的工程收益**，你们做贸易审批流时体会过。

### 第三层：省状态与恢复的可靠性（最值钱的一层）

手写版进程一崩、input() 一挂、部署一重启，Agent 状态全丢。框架的 checkpointer 让**每一步自动落盘**：崩溃从最近 checkpoint 恢复、人工确认可以挂起几小时甚至几天、改错还能时间旅行回滚。这一层手写要付出"消息队列 + 状态库 + 恢复协议"的全套代价——**框架 80% 的价值在这层**。

> 优先级要点：选框架先看第三层（持久化与人审），再看第二层（控制流表达力），第一层只是顺手。

## 3. 框架永远帮不了你的四件事

1. **业务规则本身**：点价窗口期校验、基差报价合规规则——框架不知道什么是"点价"。
2. **Prompt 质量**：抽取报盘要素的准确率取决于 prompt + 模型，不取决于 StateGraph。
3. **评估数据集**：框架自带 eval 工具（06 篇），但评估集纪律要靠 006 篇的 methodology 自己建。
4. **领域边界设计**：哪些动作该人审、哪些可自动，是风控决策，不是框架决策。

**费曼检验**：如果把框架从项目里删掉，你的业务逻辑应该一行都不用改——改不了的，说明你把业务逻辑泄漏进框架了，这是 05 实战篇反复强调的写法纪律。

## 4. Java 工程师类比：框架 = Spring

你对"框架换控制权"其实早有体感：

| Java 世界 | Agent 框架世界 | 共同代价 |
|---|---|---|
| 手写 Servlet | 手写 Agent 循环 | 全都要自己来 |
| Spring IoC 接管对象装配 | LangGraph 接管执行流转 | 控制权交给框架，换可维护性 |
| Spring 事务管理 | checkpointer 持久化 | 声明式 vs 手写 commit |
| Actuator / Micrometer | trace/span 自动埋点 | 统一可观测口径 |
| 换框架 = 伤筋动骨 | LangChain 0.x→1.0 断代 | 锁定生态的风险 |

Spring AI 的定位正是"把 LLM 当成新一代 JDBC"——Spring 三十年来干的都是"把异构系统抽象成可移植接口"，LLM 只是新加入的抽象对象（来源：守株阁《Spring AI 深度》，2026-05）。所以 Java 团队学框架概念的最快路径：**先认共性件（03 篇五层解剖），再映射回 Spring 心智**。
