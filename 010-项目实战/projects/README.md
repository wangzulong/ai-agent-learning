# projects：六个项目怎么串、练什么能力

> 【一句话人话】六个项目不是六座孤岛——01→03→06 是一条主线流水线，02/04/05 是三条独立支线；每个项目各自回扣 001~009 中的特定能力。

【生活类比】主线像连锁餐厅的开店流程：先学会做招牌菜（01 抽取），再把招牌菜接上外卖订单系统（03 分流），最后开成中央厨房统一调度（06 多 Agent 协作）。支线像甜品店、咖啡店、快餐店，各有各的供应链，随时可以单独开业。

              └─────────────┘  └─────────────┘  └─────────────┘
                 001+005          005+006          003+009
                 RAG+长文档       RAG+MCP          LangGraph

### 主线：01 → 03 → 06

| 边 | 传递什么 | 具体接口 |
|---|---|---|
| 01 → 03 | 03 的点价处理链调用 01 的抽取服务 | `POST http://localhost:8101/extract` |
| 03 → 06 | 03 识别出的点价邮件触发 06 的评审任务 | 大额单转发 `POST http://localhost:8106/review` |
| 01 → 06 | 06 的 Worker 直接复用 01 抽取的要素字段 | 同 8101 服务 |
| 04 → 06（弱依赖） | 06 的风控 Agent 可复用 04 的 MCP 查询工具 | MCP `query_inventory` / `get_future_price` |

### 支线：02、04、05 相对独立

- **02 合同审查**：唯一前置是 RAG 能力本身，与其他项目零接口依赖，可随时开。
- **04 库存问答**：数据层（MCP 工具）以后可被 06 复用，但 04 自身不需要任何前置项目。
- **05 费用审核**：LangGraph 练手场，完全独立。

## 二、每个项目训练 001~009 的哪些能力

| 项目 | 回扣能力编号 | 具体练什么 |
|---|---|---|
| 01 点价要素抽取 | **001 + 004** | Prompt 结构化输出规范；function calling 工具 schema 设计、enum 收窄、多工具调用 |
| 02 合同审查 | **001 + 005** | 长文档切分策略（条款级）、embedding 检索、引用可核验、RAG+LLM 混合链路 |
| 03 邮件分流 | **003** | 两层级联路由（规则先行 LLM 兜底）、置信度阈值、兜底通道设计 |
| 04 库存问答 | **005 + 006** | RAG 检索制度文档；MCP 工具封装、只读白名单、最小权限 |
| 05 费用审核 | **003 + 009** | 分层审核思想（路由）；LangGraph 状态图、条件边、图先纸上后代码 |
| 06 评审小组 | **007** | Supervisor 模式、Worker 窄职责、并行分发、汇总裁决、失败隔离 |
| （全部） | 002/008 贯穿 | 每个项目的"数据准备"贯彻 002 数据工程意识；"评估/运营"贯彻 008 评估与可观测意识 |

> **注意**：002（数据工程）和 008（评估与可观测）没有单独对应的项目，因为它们不是"一个功能"，而是**贯穿所有项目的地基**——假数据生成是 002 的练习，评估集+监控+bad_case 闭环是 008 的练习。做完六个项目，这两章也就融会贯通了。

## 三、推荐学习路径

### 路径 A：顺序全跑（约 17 周）

```
01(2周) → 02(3周) → 03(2周) → 04(3周) → 05(3周) → 06(4周)
```

适合：时间充裕、想完整复刻整个 CTRM AI 体系。

### 路径 B：主线冲刺（约 8 周）

```
01 → 03 → 06（04 的 MCP 工具可以后补）
```

适合：想尽快体验多 Agent 协作，主线上能力密度最高。

### 路径 C：按需单点（2~3 周/个）

从 02 / 04 / 05 里挑与本职工作最痛的一个先做，用最小成本在公司内部验证"AI 真有用"，拿结果换资源再跑主线。

## 【本章自测】

1. 主线是哪三个项目、按什么顺序、为什么？——要点：01→03→06；01 提供抽取服务，03 提供邮件触发，06 组装两者成多 Agent 评审。
2. 02/04/05 为什么相对独立？——要点：各自能力闭环（RAG / MCP+RAG / LangGraph），对外零接口依赖；04 的工具层可被 06 弱依赖复用。
3. 002 和 008 为什么没有专属项目？——要点：它们是贯穿性地基——假数据=002 练习、评估+监控+坏例闭环=008 练习，做完六项目自然融会贯通。
4. 三条学习路径分别适合什么人？——要点：A 顺序全跑（时间充裕）、B 主线冲刺（想快速体验多 Agent）、C 按需单点（用最痛场景换公司资源）。
