# 03 - 客商邮件分流路由（能力回扣：003 Routing Workflow）

> 【本项目问题】① 公共客服邮箱每天 300+ 封，点价指令、对账争议、物流跟踪、垃圾邮件混在一起，人工分拣要 3 小时；② 分错部门来回踢皮球，点价类邮件超时 2 小时就可能错过行情窗口；③ 三类邮件的处理 SLA 不同，需要不同的处理链。

## 项目卡片

| 项 | 内容 |
|---|---|
| 难度 | ★★ |
| 预计投入 | 2 周（每天 2 小时） |
| 前置知识 | 003 Routing Workflow、关键词规则 + LLM 混合分类 |
| 产出物 | 邮件自动分类器 + 三条处理链（点价链/争议链/物流链） |

---

## 一、需求定义

### 用户故事

```
作为 客服主管，
我想要 公共邮箱的邮件自动分流到点价组、结算组、物流组（垃圾邮件直接归档），
以便 点价类邮件 5 分钟内送达交易台，总体人工分拣时间从 3 小时降到 0.5 小时。
```

### 验收标准

| 线 | 标准 |
|---|---|
| 质量线 | 四分类准确率 ≥ 0.95；点价类邮件误路由率 < 1%（宁可多路由不可漏） |
| 性能线 | 单封分类 P95 < 5s |
| 兜底线 | 置信度不足或"无法判断"时路由到人工分拣台，绝不静默丢弃 |

---

## 二、架构设计

![邮件分流项目架构](../diagrams/010-05-邮件分流项目架构.svg)

链路说明：邮件网关拉信 → 预处理（去签名/去历史引用）→ **两层路由**：第一层关键词规则（快、免费、处理 80% 明显样本），第二层 LLM 分类（只处理规则拿不准的 20%）→ 按类别进入三条处理链：① 点价链：调 01 项目的抽取服务，生成待办卡片推交易台；② 争议链：抽取争议金额与合同号，生成工单；③ 物流链：解析船名/港口/日期，查库存表后自动回复模板邮件。垃圾邮件归档。

**路由设计核心（003 回扣）**：规则先行、LLM 兜底——能用 `if` 解决的不花 token，LLM 只在模糊地带出场；置信度低就走人工通道。

```python
# project_03/preprocess.py
import re

def clean(text: str) -> str:
    """去引用行/签名区，压缩到分类所需最小信息"""
    lines = [ln for ln in text.splitlines()
             if not ln.startswith(">") and "原始邮件" not in ln]
    body = "\n".join(lines)
    body = re.split(r"--\s*\n|此致|Best regards", body)[0]
    return body.strip()[:800]
```

```python
# project_03/router.py —— 规则先行，LLM 兜底（003 核心）
import json
from openai import OpenAI
from preprocess import clean

client = OpenAI()
LABELS = ["pricing", "dispute", "logistics", "spam"]

RULES = [
    ("pricing",   ["点价", "基差", "贴水", "升水", "basis"]),
    ("dispute",   ["对账", "异议", "发票", "不符", "差异"]),
    ("logistics", ["船期", "到港", "提货", "船名", "物流", "滞期"]),
    ("spam",      ["优惠", "理财", "年化", "抢购", "名额有限"]),
]

def rule_route(text: str) -> tuple[str | None, float]:
    body = clean(text)
    hits = {}
    for label, kws in RULES:
        n = sum(1 for kw in kws if kw in body)
        if n:
            hits[label] = n
    if not hits:
        return None, 0.0
    best = max(hits, key=hits.get)
    # 置信度 = 命中数占比；多类同时命中且接近则不自信
    total = sum(hits.values())
    conf = hits[best] / total if total > 1 else 0.6
    if len(hits) > 1 and sorted(hits.values())[-1] - sorted(hits.values())[-2] == 0:
        conf = min(conf, 0.55)  # 平票 → 不可信
    return (best, conf) if conf >= 0.8 else (None, conf)

LLM_PROMPT = """你是邮件分类器。把邮件分入且仅分入：pricing(点价指令)、
dispute(对账/费用争议)、logistics(船期/物流/提货)、spam(营销垃圾)。
只输出 JSON：{"label": "...", "confidence": 0~1}。无法判断则 label="unknown"。"""

def llm_route(subject: str, text: str) -> dict:
    resp = client.chat.completions.create(
        model="gpt-4o-mini", temperature=0,
        response_format={"type": "json_object"},
        messages=[{"role": "system", "content": LLM_PROMPT},
                  {"role": "user", "content": f"主题：{subject}\n正文：{clean(text)}"}],
    )
    return json.loads(resp.choices[0].message.content)

def route(subject: str, text: str) -> dict:
    label, conf = rule_route(text)
    if label:                                   # 第一层：规则
        return {"label": label, "confidence": conf, "by": "rule"}
    r = llm_route(subject, text)                # 第二层：LLM
    if r.get("label") not in LABELS:            # 兜底线：unknown 走人工
        return {"label": "manual", "confidence": r.get("confidence", 0),
                "by": "llm-unknown"}
    return {"label": r["label"], "confidence": r["confidence"], "by": "llm"}
```

### 阶段 3：三条处理链（commit: `feat: three processing chains`）

```python
# project_03/chains.py —— 各类邮件的后续动作
import json, urllib.request

EXTRACT_URL = "http://localhost:8101/extract"   # 01 项目服务

def handle_pricing(mail: dict, route_result: dict) -> dict:
    req = urllib.request.Request(
        EXTRACT_URL, data=json.dumps({"text": mail["body"]}).encode(),
        headers={"Content-Type": "application/json"})
    try:
        with urllib.request.urlopen(req, timeout=5) as resp:
            ext = json.loads(resp.read())
    except Exception:
        ext = {"ok": False, "needs_human": True}   # 01 服务挂了 → 转人工
    return {"chain": "pricing", "todo": "推交易台", "extract": ext}

def handle_dispute(mail: dict, route_result: dict) -> dict:
    import re
    m = re.search(r"INV-\d+", mail["body"])
    amount = re.search(r"(\d+)\s*万?元", mail["body"])
    ticket = {"type": "dispute", "invoice": m.group(0) if m else None,
              "amount_wan": amount.group(1) if amount else None,
              "priority": "high"}
    return {"chain": "dispute", "ticket": ticket, "todo": "建工单推结算组"}

def handle_logistics(mail: dict, route_result: dict) -> dict:
    import re
    ship = re.search(r"[\u4e00-\u9fa5]{2,4}\d{3}", mail["body"])
    reply = (f"您好，{ship.group(0) if ship else '您咨询'}的船期已收到，"
             "物流专员将在 2 小时内回复确认。")       # 先确认后跟进，不在链里幻觉船期
    return {"chain": "logistics", "auto_reply": reply, "todo": "推物流组"}

def handle_spam(mail: dict, route_result: dict) -> dict:
    return {"chain": "spam", "todo": "归档"}

HANDLERS = {"pricing": handle_pricing, "dispute": handle_dispute,
            "logistics": handle_logistics, "spam": handle_spam}

def dispatch(mail: dict, route_result: dict) -> dict:
    if route_result["label"] == "manual":
        return {"chain": "manual", "todo": "人工分拣台"}
    return HANDLERS[route_result["label"]](mail, route_result)
```

### 阶段 4：评估（commit: `test: routing eval`）

```python
# project_03/eval.py
import json
from router import route

def run_eval(path="eval/mails_gold.jsonl"):
    total = correct = price_err = 0
    for line in open(path, encoding="utf-8"):
        m = json.loads(line)
        r = route(m["subject"], m["body"])
        total += 1
        correct += (r["label"] == m["label"])
        # 点价类误路由单独统计（SLA 最敏感）
        if m["label"] == "pricing" and r["label"] != "pricing":
            price_err += 1
    return {"acc": round(correct / total, 3),
            "pricing_misroute": price_err,
            "pricing_misroute_rate": round(price_err / total * 4, 3)}

if __name__ == "__main__":
    print(run_eval())
```

from fastapi import FastAPI
from pydantic import BaseModel
from router import route
from chains import dispatch

app = FastAPI(title="mail-router-agent")

class MailIn(BaseModel):

@app.post("/ingest")
def ingest(mail: MailIn):

    action = dispatch(mail.model_dump(), r)

## 六、上线与运营

| 档位 | 做法 |
|---|---|
| 影子模式 | 路由结果只写日志，人工照旧分拣，比对一周 |
| 白名单 | 点价类先自动化（SLA 最痛），其余仍人工 |
| 全量 | 四类全自动，manual 通道保底 |

**降级**：LLM 超时 → 纯规则路由；规则也没信心 → 全部进人工分拣台。
**监控**：各路由层占比（rule/llm/manual）、点价邮件 5 分钟送达率、误路由人工纠正数。
**运营要点**：每封被人工纠正的邮件自动登记 bad_case，周五集中分析补规则关键词。

## 七、常见坑

| 坑 | 现象 | 解法 |
|---|---|---|
| 一封邮件两个意图 | "点价并问船期" | 主意图分类 + 处理链内二次识别；或允许多标签输出 |
| 历史引用污染 | 回复邮件带上月正文被分类错 | preprocess 截断历史引用（`>` 行、签名后内容） |
| 规则关键词误伤 | 客户名字带"基差"被路由点价 | 关键词命中数阈值 + 平票判 0.55 转入 LLM |
| LLM 分类摇摆 | 同一封邮件两次分类结果不同 | temperature=0 + 输出限定枚举 + 置信度阈值 |
| 误路由统计口径 | 准确率高但点价误路由超标 | 点价类误路由单独设红线指标（本卡验收线） |

## 【本项目自测】

1. 为什么"规则先行、LLM 兜底"而不是全用 LLM？——要点：80% 样本规则可判（零成本零延迟），LLM 只处理模糊 20%；规则层也更容易被人理解和修正。
2. 平票时置信度为什么压到 0.55？——要点：两类关键词同时命中说明信号矛盾，硬选会误路由，压低置信度让它落到 LLM 或人工层。
3. 点价链为什么在调 01 服务失败时返回 needs_human 而不是重试到成功？——要点：点价 SLA 5 分钟，重试耗时会错过行情窗口；宁可人工录入也不延迟。
4. 误路由率为什么单独给点价类设红线？——要点：四类整体准确率会被 spam 高准确率稀释，点价类错成本最高（错过行情=真金白银）。
5. unknown 转 manual 的比例多少算健康？为什么不是越低越好？——要点：5~10%；过低说明模型"过度自信"把模糊样本也硬分，manual 通道是安全阀不是缺陷。
6. 本项目的路由结构对应 003 篇的哪种模式？——要点：两层级联路由（cascade routing）+ 静默兜底通道。
