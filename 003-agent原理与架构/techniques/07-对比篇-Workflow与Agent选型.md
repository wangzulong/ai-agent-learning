# 07 - 对比篇：Workflow 与 Agent 选型

## 1. 核心裁定：Anthropic 的第一原则

《Building effective agents》（2024-12）最常被引用的一句话：**"Find the simplest solution possible"——能用 workflow 解决的，绝不引入 agent；能单次调用解决的，绝不引入 workflow。**

**为什么**：自主性每升一级，成本、延迟、评估难度、失败模式数量都同步上涨（见 03 篇频谱图）。Agent 的价值在于**路径不可预测**的任务；路径可预测的任务，用代码写死路径反而更便宜、更稳、更好评。

| 判断信号 | 选型 |
|---|---|
| 输入格式稳定、步骤固定（表单抽取→校验→落库） | 单次调用 / prompt chain |
| 输入类型多样但处理路径有限（邮件分几类走不同流程） | **routing** |
| 各部分互不依赖、要速度（多份合同并行审查） | **parallelization** |
| 任务要先规划再分派、结果要汇总（批量点价方案生成） | **orchestrator-workers** |
| 有明确质量标尺、生成物需要打磨（合同条款建议稿） | **evaluator-optimizer** |
| 步骤无法预知、需要模型临场决定查什么、调几次（开放式客商邮件处理） | **agent** |

## 2. 五种工作流模式速查（细节图见 04 篇）

| 模式 | 一句话人话 | 代价 | 点价场景示例 |
|---|---|---|---|
| Prompt Chaining | 流水线，前一道工序的产出是后一道的原料 | 延迟串行叠加 | 抽取要素 → 查价 → 生成建议稿 |
| Routing | 前台分诊台，按类型转专科 | 分类错了全错 | 点价申请 / 询价 / 投诉邮件分流 |
| Parallelization | 多个窗口同时办业务，最后汇合 | 结果聚合逻辑要写 | 同一邮件里的多个品名并行查库存 |
| Orchestrator-Workers | 项目经理拆任务派工，收货汇总 | 两跳 LLM 成本 | 批量点价：先拆分商品行，再逐行查价建单 |
| Evaluator-Optimizer | 作者-审稿人循环打磨 | 轮数不可控（要设上限） | 建议单生成后自检业务规则再修订 |

## 3. 自主性频谱：选型决策树

用 03 篇的频谱做决策（从右往左收缩，直到失败风险可控）：

```text
任务路径可完全预知吗？
├─ 是 → 写代码（workflow / chain），模型只做单步
└─ 否 → 模型需要临场决定"查什么"吗？
        ├─ 否 → routing / parallelization 够用
        └─ 是 → 每步错误代价高吗？
                ├─ 高 → agent + 强人在环（高危挂起）
                └─ 低 → agent 全自动 + 事后抽检
```

**费曼检验**：为什么生产系统大量是"workflow 骨架 + 局部 agent"？——骨架保证可预测可审计（老板和审计要的），agent 只放在真正需要临场判断的节点（模型才值钱的）。全 agent 化是把两者优点都丢掉。

## 4. 与传统工作流引擎的关系（Java 开发者视角）

| 维度 | Flowable / Activiti | LLM Agent |
|---|---|---|
| 路径定义 | 人画 BPMN 图，确定性执行 | 模型临场规划，概率性 |
| 节点逻辑 | 代码 / 规则引擎 / 脚本 | LLM 调用 + 工具 |
| 适合 | 步骤固定、要审计合规（贷款审批流） | 步骤随输入变化、自然语言驱动 |
| 失败处理 | 边界事件、补偿事务 | 重试 + 降级 + 人在环 |
| **正确姿势** | **混合：BPMN 做骨架，LLM 节点做"智能工位"** | 同左 |

在 CTRM 里落地：点价审批主流程留在 Flowable（合规审计要确定路径），"邮件要素抽取"和"库存方案建议"两个 LLM 节点嵌进去——这就是"workflow 骨架 + 局部 agent"。

## 5. 主流编排框架一览（详细的留给 009 篇）

| 框架 | 出身 | 一句话定位 |
|---|---|---|
| LangGraph | LangChain | 图状态机，显式控制流，生产采用最多 |
| OpenAI Agents SDK | OpenAI | 轻量，handoffs 交接 + guardrails 护栏 |
| Anthropic Claude Agent SDK | Anthropic | 与 Claude 生态深度绑定，长任务三招内置 |
| CrewAI | 社区 | 角色化多 agent，上手快，控制粒度粗 |
| AutoGen | 微软 | Actor 模型对话式多 agent，科研味浓 |

**本篇只解决"要不要框架"**：手写循环（05 篇 100 行）能跑通一切原理；框架买的是 checkpoint、并发、可视化、重试这些**工程件**。业务复杂到手写开始疼（通常是有并行分支、需要断点恢复时），再上框架。
