# 08 - 自测篇：题库与面试题

> 【本节问题】① 概念记得牢不牢？② 原理讲得清不清？③ 工程决策做不对？④ 面试怎么答才显功力？

> 用法：先遮住答案自测；答错的题回到对应篇章重读；按文末间隔重复计划复习。

---

## L1 概念层（回 02 概念篇）

1. 用最小公式定义 Agent，四个成分各去掉一个会怎样？
   > 要点：Agent = LLM + 工具 + 循环 + 目标。去掉工具=只会说不会做；去掉循环=单次调用无多步；去掉目标=无终止条件烧钱；去掉 LLM=传统自动化脚本。
2. workflow 和 agent 的本质区别一句话？
   > 要点：路径谁决定——代码预定义（workflow）vs 模型临场规划（agent）。
3. Orchestrator-Workers 和 Parallelization 的区别？
   > 要点：前者先有"拆解规划"再派工（两跳 LLM）；后者任务天然独立、直接并发（一跳）。
4. 什么是 agentic eagerness？（联动 004）
   > 要点：agent 对"何时停、何时继续"的倾向性；早停误事 vs 过度坚持烧钱，用早停标准和步数预算校准。
5. 人机协同的三个自主级别怎么分？
   > 要点：读操作全自动 / 写操作自动+可回滚 / 高危动作强制人工确认。

## L2 原理层（回 03 原理篇）

6. 画出 Agent 核心循环的五个阶段，并指出状态存在哪里。
   > 要点：获取上下文→LLM 决策→执行工具→观察回填→终止判断；状态 = messages 历史 + 外部 state（数据库/结构化笔记）。
7. 为什么"把全部历史塞回上下文"在长任务中会失效？
   > 要点：attention budget 摊薄 → context rot（001 篇）；成本线性上涨；解药是 compaction / structured notes / sub-agent 三招。
8. ReAct 和 Plan-and-Execute 的本质差异？各举一个适用场景。
   > 要点：ReAct 交替思考-行动（适合探索型、路径未知）；Plan-Execute 先出全计划再执行（适合结构化多步，中途可控可审计）。
9. Reflexion 的反思信息存在哪、为什么有效？
   > 要点：存在循环外的记忆/笔记里而非对话历史；下次尝试带上"上次为什么失败"，把失败变成先验（类比：错题本）。

## L3 工程设计层（回 05/06 篇）

10. 手写循环必须有的四个工程件？
    > 要点：工具注册与 schema 校验、步数预算 MAX_STEPS、工具结果回填的 role 管理、终止条件（final_output 工具或 stop_reason 判断）。
11. 点价 Agent 里 `submit_pricing_proposal` 为什么要设计成"挂起等确认"而不是直接落库？
    > 要点：写操作+高风险；分级自主原则；挂起也给了人工纠错窗口，失败成本从"错误点价"降到"看一眼建议单"。
12. 30 步后 Agent 开始重复调用同一工具，列出你的排查顺序。
    > 要点：① 是否步数预算/早停缺失；② 工具返回是否被截断导致模型重试；③ 目标漂移（计划没外置）；④ context rot 早期指令被稀释；⑤ 工具描述含糊导致选择混乱。

## L4 综合设计题（面试压轴）

13. **设计题**：为 CTRM 设计"客商邮件自动处理 Agent"，画架构并说明每个节点的自主级别与护栏。
    > 参考答案要点：入口 routing（点价/询价/投诉/垃圾）→ 点价链：抽取（低危自动）→ 查库存查价（低危自动）→ 生成建议单（自动+挂起）→ 交易员确认（人工）→ 回复邮件（高危，白名单模板+人工点击发送）；护栏：输入注入隔离、工具白名单、输出业务规则校验；评估：30 封邮件回归集 + 步数/成本监控。
14. **辩论题**：老板要求"把审批流全部 Agent 化，彻底智能"。你怎么劝？
    > 要点：审批路径固定且要审计——workflow 是更优解（便宜、确定、可回滚）；Agent 化反而引入不可预测性，审计无法通过；正确方案是 BPMN 骨架 + 智能节点；引用 Anthropic"最简方案"原则。
