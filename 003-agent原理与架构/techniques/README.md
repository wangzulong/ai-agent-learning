## 💼 贯穿案例：CTRM 点价申请 Agent

**业务背景**：客户发来邮件申请点价（例如"请按明天上午 M2505 合约基差 -80 的条件，点 500 吨"），需要：理解邮件 → 抽取要素 → 查库存与期货价 → 生成点价建议单 → 交易员确认 → 写回 CTRM。

各篇对该案例的切入角度：

| 篇章 | 案例 used for |
|---|---|
| 01 | 为什么"一封邮件进来"就打穿了单次调用的能力边界 |
| 02 | 工具、会话状态、终止条件在点价流程里的实例化 |
| 03 | 点价 Agent 的一轮循环长什么样（状态里有什么） |
| 04 | 抽取→查价→建议单 = prompt chaining + routing；建议单质检 = evaluator-optimizer |
| 05 | 完整可跑的 Python 最小实现（工具注册/循环/护栏） |
| 06 | 点价场景的四大高危失败模式与缓解 |
| 07 | 为什么点价主链路应当 workflow 化、Agent 只做局部 |
