# 003 - Agent 原理与架构 学习专题

> 这是 AI Agent 学习路线的**发动机层**。002 讲清了"引擎"（LLM 本体），本专题讲"传动系统"——如何让一个只会接龙的模型，变成能拿目标、用工具、跑循环、自己判断何时收工的 Agent。核心公式先放在这里：**Agent = LLM + 工具 + 循环 + 目标**。学完本专题，你能看懂 LangGraph/OpenAI Agents SDK 的每个抽象，也能不用框架手写一个生产可用的 Agent 循环。

## 🔗 与其他目录的关系

- 承接 `001-prompt工程`：Agent 的 system prompt 写法直接复用 001 的"六件套 + 正确海拔"；001 的 agentic eagerness（催促模型直接行动）是 06 篇"死循环失败模式"的缓解手段之一
- 承接 `002-llm基础`：循环里的每一次模型调用都是 002-03 篇那趟"从 token 到回答的旅程"；上下文窗口、KV cache、prompt caching 直接决定 Agent 循环的成本曲线
- 联动 `008-记忆与上下文工程`：本专题 06 篇只讲"循环内的上下文管理"（压缩/子代理/结构化笔记），跨会话记忆体系在 008 展开
- 本专题是 `009-agent框架实战` 的理论地基：先懂循环原理，再看框架才不会"只会调 API 不懂抽象"

## 📌 贯穿案例：CTRM 点价申请 Agent

为贴合业务（中基集团 CTRM 系统），全专题用同一个案例贯穿：

```text
客户邮件进来 → 抽取要素（品种/数量/基差/月份）→ 查库存与期货价
→ 生成点价建议单 → 人工确认 → 写回 CTRM
```

每个篇章都会回答：这一环**为什么**需要 Agent 架构（01）、用到哪些**概念**（02）、循环怎么**转**（03）、编排怎么**选**（04）、**代码**怎么写（05）、**护栏**怎么加（06）、**为什么不全用 workflow**（07）。
