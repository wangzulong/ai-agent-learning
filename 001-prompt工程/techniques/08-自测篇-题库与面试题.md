## L1 概念题（会就行，答不上说明 01-02 篇没吃透）

1. prompt 工程的一句话定义？它和"会说话就会写提示词"的区别？
2. System / User / Assistant 三角色的职责与优先级顺序？
3. ICL 的全称与含义？它与微调的本质区别？
4. zero-shot 和 few-shot 的区别？few-shot 六个设计决策是什么？
5. CoT 是什么？对推理模型为什么是反模式？
6. temperature 控制什么？temperature=0 能保证正确吗？
7. 结构化输出的三层强度？生产上推荐哪层？
8. context rot 是什么？它推翻了"窗口大就能随便塞"的什么直觉？
9. 直接注入 vs 间接注入的区别？
10. The Prompt Report 六大门类（六字诀）？

## L2 应用题（要能展开说，对应 03-05 篇）

1. 为什么"长文档放前面、问题放最后"？用 attention 权重解释。
2. "引文接地"是什么？为什么它能显著降低幻觉？
3. 设计 few-shot 示例时，为什么必须包含边界负例？举一个抽取任务的例子。
4. Anthropic 的"正确海拔"原则：写一条"刚好"的规则，并写一条"太低"和一条"太高"的反例。
5. 手写结构化输出修复循环的伪代码，说明 error_hint 的作用。
6. 你的提示词上线后格式偶尔不合法，排查顺序是什么（至少 4 步）？
7. 通用模型提示词迁移到推理模型，要做哪三类修改？
8. Prompt Caching 为什么能省钱？生效条件是什么？你的 CTRM 抽取场景哪些部分适合做稳定前缀？

## L3 场景设计题（对应 05-07 篇，纸面设计）

1. **场景**：从客户邮件抽取点价申请要素（品名/数量/升贴水/点价区间/交割月），要求：缺失字段不编造、多品名支持、低置信度标红。请写出完整 system prompt + user 消息结构，并说明每个设计点的失效风险。
2. **场景**：同一套提示词要同时适配 GPT-5 和 DeepSeek-V4（成本路由），列出需要适配的四个机械点和一个内容适配点。
3. **场景**：合同审查 Agent 要读外部网页获取最新税率，如何设计防间接注入？（至少三层防御）
4. **场景**：上线三个月后人工复核率从 5% 涨到 18%，给出完整排查方案（提示：模型静默升级、上游数据、评估集盲区）。
5. **场景**：老板要求"准确率再提 3 个点，成本不许涨"。给出至少 4 个可尝试手段及预期代价。

## L4 面试题（大厂 Agent 岗真题风格）

1. 谈谈你对 "prompt engineering is dead" 的看法，结合 context engineering 的兴起。（考趋势判断）
2. 为什么 ICL 有效？讲一个学术假说并用工程语言翻译。（考原理深度）
3. 设计一套提示词的 CI 流水线：commit 触发什么、评估集怎么管理、judge 怎么校准、怎么防止"评估集过拟合"。（考工程体系）
4. LLM-as-judge 的系统性偏差有哪些？（自我偏好、位置偏差、长度偏好、rubric 歧义）如何校准？
5. few-shot 示例数量从 3 加到 30，通常会发生什么？（边际递减 + 成本 + 可能的格式过拟合）什么时候值得加？
6. 解释 temperature、top_p 的区别；为什么新一代 Claude 直接禁用了它们？（自适应取代手动控制）
7. 你的 Agent 在长会话中越答越差，从提示工程和上下文工程两个角度分别给方案。（compaction、结构化笔记、历史裁剪 → 联动 008）
8. 如何让模型在"不确定"时如实暴露不确定，而不是硬答？（confidence 字段、允许 null、"引用原文"接地、评估时统计校准曲线）
9. 什么情况下你会放弃 prompt 优化直接换模型 / 换架构（上 RAG / 上微调）？决策依据是什么？
10. 给一个完全不懂 AI 的同事解释：为什么提示词要进 Git、要写测试、要走 code review？

## 📅 间隔重复计划（Spaced Repetition）

|---|---|
